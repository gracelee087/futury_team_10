# SÜSIE · Selected Prüfakte theme system

## Authority and scope
The user selected Prüfakte and requested Casual and High Contrast, each in light and dark. The selected concept uses pruefakte.html, pruefakte.css, theme-init.js and pruefakte.js; themes.js was merged into pruefakte.js in the T10-031 pass and removed. Evidenzdesk, Prüfpfad, styles.css and app.js remain historical alternatives. Synthetic fixtures, human review and blocked release remain explicit. Since T10-031 (2026-10-26, human directive) the app can run backend-wired against the itsg store via the stdlib bridge `itsg/webserver.py` (`/api/state`, `/api/run`, `/api/health`); when unreachable it falls back to clearly-labelled synthetic data with an explicit offline badge. No certification or legal-compliance authority.

## Direction and typography
Achromatic ledger: neutral chrome, tabular right-aligned values, a visible source-to-output evidence chain and German comparison labels. Arial, "Helvetica Neue", sans-serif is an operationally stable stack, not a new typographic identity. No proprietary fonts are distributed. The former unavailable Calibri face is not claimed as installed. Rem-based typography scales with the root size: Casual body 1.0625rem (17px at the default root), High Contrast 1.125rem (18px). Evidence metadata and support copy use .875rem (14px); contrast evidence citations and labels use 1rem. Default heading sizes are 1.75rem, 1.3125rem and 1.125rem, with responsive and contrast adjustments. No entrance animation.

## Appearance and navigation
Darstellung exposes Casual / Hoher Kontrast and Hell / Dunkel with aria-pressed buttons. Appearance and language preferences use localStorage key susie-appearance; storage failure is nonfatal. Query parameters theme=casual|contrast, mode=light|dark and lang=de|en override saved choices; the initial language follows the browser (German otherwise). Synchronous theme and language initialization precede CSS. Mobile and tablet initially collapse the settings disclosure. Case query parameters and view hashes support navigation; the first non-PASS case is selected by default. A theme-cycle icon button in the sidebar rotates casual/light → casual/dark → contrast/dark → contrast/light. The rail quick-controls carry the cycle button and an EN/DE segmented control; the settings menu groups Lesethema, Farbmodus, Sprache and API configuration (backend URL — empty = same origin — connection check, offline re-run, live LLM re-run behind a two-step confirm; credentials never reach the browser). A connection badge in the topline shows backend state in both languages.

Elevation: the sidebar is a raised surface over the canvas (offset+blur shadow tokens on Casual light/dark; High Contrast deliberately uses a 1px border instead of shadows, forced-colors safe), and work surfaces carry one subtle shadow step. Motion stays minimal: the existing cancellable 160ms opacity feedback gained a 4px translateY, plus quiet background/box-shadow transitions on interactive elements; all of it collapses under prefers-reduced-motion.

## Review interaction and storage
The standalone script owns the UI state; its data source is either the backend store (via /api/state: 4 typed cases with full DTA field dicts, source, criteria, report/conformance) or the three synthetic cases with the same normalized shape. Backend case content (reasons, citations, expected bases) stays in its source language (German); all UI chrome is bilingual. The evidence panels render the primary (first mismatching) field large and the remaining DTA fields as key/value rows with mismatches highlighted. TC-002/TC-2 is labelled Abweichungsfall and its provenance identifies a synthetic deviation against a reference value. TC-003 identifies missing input with no approved expected-value basis. Selection uses a raised surface and 1px control-color outline; accessible case buttons expose the current selection; on any viewport, selecting a case scrolls the detail into view only when it sits outside a comfortable reading position. Search (field names and values), result filtering, empty-state reset, the "Klärungspunkte klären" non-PASS toggle, sortable columns, source navigation and a literal JSON output exhibit support review. The Belegkette strip is live: Quellreferenz is a working link to the sources view and the Prüffall stage is marked as the current one.

Per-case drafts and saved notes use sessionStorage key susie-review-tab-v1, version 1. They restore on reload in the same tab; they are not durable records or synchronized decisions. When browser storage is denied, the helper explains that notes survive only until reload and recommends JSON export. Notes are limited to 2,000 JavaScript string code units and 100 saved entries. Restored data is bounded and checked; note rendering uses literal text — in the report note list as well. Ctrl/Cmd+Enter saves a valid note without changing the case's review state; the field help names the shortcut. Export includes the data-source provenance, findings, saved notes and unsaved per-case drafts, and always `compliance_claim: false`. Release remains disabled with a visible explanation. The report view lists saved notes and drafts (the review record is visible at the finish line), saved notes can be deleted through a two-step inline confirm, case rows carry a draft marker while an unsaved draft exists, and the table wrapper is only keyboard-focusable when it can actually scroll.

## Motion, adaptation and print
User-triggered view, evidence and disclosure updates use a cancellable 160ms opacity feedback (.72 to 1). New feedback cancels prior animation. Reduced-motion preference skips animation and cancels active feedback when it changes; hiding the document also cancels it. There is no initial entrance animation.

The layout uses a desktop sidebar, a top navigation layout at 701–1100px, and labelled case cards at 700px and below. Mobile evidence panels stack; the current selected app no longer requires the former sideways-table hint. Long content wraps, controls meet the declared touch sizing, and the mobile safe area is respected. Print CSS hides navigation and editing controls, restores the table presentation and prints the active review surface. Forced-colors rules preserve control boundaries and active outlines.
